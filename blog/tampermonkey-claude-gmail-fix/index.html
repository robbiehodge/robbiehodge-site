My Gmail Search Bar Broke. The Fix Was One Screenshot Away.

Published
October 19, 2026
Read Time
4 min read
Category
AI Tools · Productivity

I got a new ultrawide monitor last week. It's great for everything except, apparently, Gmail.

Something about the extra width crammed Gmail's UI into a layout it wasn't built for. The sidebar expanded. The toolbar shifted. And somewhere in that shuffle, my search bar — the one I use probably 40 times a day — stopped being clickable. The cursor would hover over it, the highlight would appear, and then nothing. Click. Nothing.

I tried the obvious fixes. Zoom levels. Different browsers. Hard refresh. Nothing worked. The search bar was visually there but functionally gone — some invisible element was sitting on top of it, eating my clicks.

My first instinct was to Google it. I found a handful of forum threads from people with similar problems, none with clear solutions. The fixes were either "try a different browser" (already did) or deep dives into Gmail's settings that didn't address a CSS overlay issue.

That's when I decided to just ask Claude.

The Screenshot Approach

I took a screenshot of Gmail with the broken search bar visible. I opened Claude, dropped the screenshot in, and described the problem: "My Gmail search bar appears but won't accept clicks on my ultrawide monitor. Something seems to be covering it. Can you help me write a Tampermonkey script to fix it?"

Claude identified the likely culprit immediately: a z-index stacking issue combined with a misaligned overlay element at ultrawide widths. Gmail's CSS wasn't tested at 3440px wide, and something was rendering on top of the search input without being visible.

The response included a complete Tampermonkey userscript — ready to paste, no modifications needed.

What is Tampermonkey? It's a browser extension that lets you run custom JavaScript on any website. You install it once, then you can add scripts that modify how pages look or behave. It's one of the most useful power-user tools on the web — and you don't need to write code to use it if Claude writes the scripts for you.

The Fix, Step by Step

Here's exactly what I did:

  1. Installed Tampermonkey in Chrome (took about 45 seconds)
  2. Opened the Tampermonkey dashboard and clicked "Create a new script"
  3. Pasted the script Claude gave me
  4. Saved it and reloaded Gmail

The search bar worked immediately. Total time from "this is broken" to "this is fixed": under five minutes.

The script Claude wrote did two things. First, it identified the offending overlay element by its Gmail-specific class and corrected its z-index. Second, it added a pointer-events: none rule to any elements that were visually hidden but still intercepting clicks at my screen width. Clean, targeted, reversible.

Why This Matters Beyond Gmail

The Gmail thing was a small problem. But the pattern it revealed is one I've started applying everywhere.

Before AI tools, "fix a broken UI element" required either technical knowledge to inspect the DOM and write CSS overrides yourself, or waiting for the software vendor to patch it (Gmail still hasn't, by the way). Now it requires a screenshot and a sentence.

I've since used the same approach to:

  • Remove an annoying promotional banner from a SaaS tool I use daily
  • Fix a date picker that rendered off-screen in a project management app
  • Add keyboard shortcuts to a web app that didn't have them
  • Auto-collapse a sidebar that kept reopening every time I navigated

None of these required me to write a single line of code. I described the problem, shared a screenshot when useful, and Claude provided a ready-to-run Tampermonkey script each time.

The Broader Shift

There's a version of this story that's just "AI is useful for debugging." But I think it's actually about something more specific: AI collapses the distance between identifying a problem and fixing it for people who aren't developers.

The traditional path was: notice problem → Google it → find a forum thread → follow instructions that may or may not apply → give up or find someone technical. The new path is: notice problem → describe it to Claude → fix it.

Tampermonkey is a good example of a tool that existed for years but stayed in the "power user" category because writing JavaScript was a barrier. That barrier is essentially gone now. The tool didn't change — the access to it did.

I expect we'll see a lot more of this. Tools that were technically available to anyone but practically available only to developers are becoming available to everyone. The unlock isn't new capabilities — it's removed friction.

The search bar fix took five minutes. The realization that I now have a general-purpose UI repair tool in my browser took a little longer to sink in.

What You Need to Try This

If you want to use this approach for your own UI frustrations:

  • Tampermonkey — free browser extension, works in Chrome, Firefox, Safari, Edge
  • Claude — describe your problem, include a screenshot if the issue is visual, ask for a Tampermonkey script
  • That's it — no coding knowledge required, scripts are sandboxed to specific websites, and you can disable or delete them instantly

The main thing to know about Tampermonkey scripts from Claude: they're site-specific. A script you add for Gmail only runs on Gmail. If Claude's first attempt doesn't fully fix the issue, describe what's still broken and ask for a revision — usually one or two iterations gets it right.

Your ultrawide monitor thanks you in advance.
